Срочные исправления по итогам разбора (2026-11-19) — этап 0 плана

Основа — архив 5503.zip. Меняются только серверные файлы; страницы сайта, тарифы и база не затрагиваются.

Что исправлено
1. Сервер не падает от обрыва соединения (monitor.js, server.js).
   Было: monitor.js ставил второй обработчик необработанных ошибок и завершал процесс на любой из них, в том числе
   на ECONNRESET / EPIPE. Фильтр безобидных ошибок в server.js из-за этого не работал: обычный обрыв связи
   перезапускал сайт у всех. Теперь обработчик один, в server.js; monitor.js только записывает ошибку и шлёт оповещение.
   Настоящая ошибка по-прежнему завершает процесс, systemd его перезапускает.
2. Терминал облачного компьютера не роняет сервер (cloud.js).
   Было: сообщение null в WebSocket терминала давало исключение и перезапуск всего приложения.
   Теперь принимаются только { d: 'ввод' } и { r: [cols, rows] }; ошибка обработчика закрывает только этот терминал.
3. Транзакции базы не отключаются после сбоя (db.js).
   Было: если BEGIN IMMEDIATE не выполнился (база занята), счётчик вложенности оставался равен 1, и все следующие
   операции до перезапуска шли без транзакции: статус платежа, дни тарифа и промокод могли разойтись.
4. Журнал панели не хранит пароли (admin/audit.js).
   Было: при смене своего пароля поле old (текущий пароль) писалось в журнал открыто и было видно роли «наблюдатель».
   Теперь для смены своего пароля и для 2FA в журнал идут только имена полей, без значений; поля old и current*
   маскируются везде. Уже сохранённые записи смены пароля и 2FA закрываются один раз, при первом запуске.
5. Файл с паролем владельца не попадает в бэкап (deploy/backup.sh).
   data/admin-password.txt исключён из архива. В базе лежит хеш этого пароля, после восстановления вход работает.
6. Уведомление Robokassa проверяется строже (billing.js).
   Подпись провайдера покрывает только MerchantLogin, OutSum и OperationId; InvId и Result в неё не входят.
   Теперь уведомление принимается, только если: MerchantLogin — наш магазин; заказ создан через Robokassa;
   сумма OutSum равна сумме заказа; операция OperationId ещё не привязана к другому заказу (привязка «операция → заказ»
   записывается один раз и не меняется). Оплаченный заказ уведомлением не отменяется. Подпись сравнивается за постоянное время.
   Отклонённое уведомление получает ответ 400 и строку в журнале сервера «Robokassa: уведомление отклонено (...)».
   Новый выключатель ROBOKASSA=off в .env: способ оплаты не предлагается, адрес уведомлений отвечает 503.

Что НЕ закрыто этим обновлением
- Robokassa: поле Result (успех или отказ) по-прежнему не подписано, а у заказов, оплаченных до этого обновления,
  номер операции не записан. Тот, кто перехватил настоящее уведомление, всё ещё может применить его к другому
  заказу на ту же сумму. Закрыть это можно только по актуальной документации провайдера или запросом статуса
  у провайдера. До такой проверки способ оплаты нужно держать выключенным: ROBOKASSA=off.
- Остальные пункты плана (этапы 1–8).
