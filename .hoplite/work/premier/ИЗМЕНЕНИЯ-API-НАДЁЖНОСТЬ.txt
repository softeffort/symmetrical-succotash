API (/v1): надёжность, деньги, безопасность
===========================================

Что исправлено
--------------
Деньги и кредиты
- Реферальный бонус: гонка закрыта. 10 одновременных запросов при бонусе 1 тратят его один раз
  (было: проходили все 10, а возвраты раздували бонус до 10).
- Возврат при обрыве клиентом до первого токена: не больше 20 раз в сутки (МСК) на пользователя.
  Поток, оборванный после начала ответа, списывается, как и раньше.
  Запросы, оборванные остановкой сервера, возвращаются всегда и в лимит 20 не входят.
- Доплата Ultra за длинный контекст считает весь запрос: tools, вызовы инструментов, tool_result, размышления, документы.
  Подписи и зашифрованные блоки (signature, encrypted_content, redacted_thinking) не считаются.
  Документ base64 считается как ~1 токен на 12 байт файла.
  Оценка делается только для Ultra-моделей.
- После ответа доплата пересчитывается по реальному числу входных токенов от провайдера, в обе стороны:
  больше оценки — добирается разница (не больше баланса), меньше — лишнее возвращается.
- В журнале API (api_log) новая колонка credits: сколько Ultra-кредитов стоил запрос (раньше было 0).
- Журнал Ultra-кредитов: запросы через API собираются в одну строку «API за день» и не вытесняют покупки и подарки.
- Возврат после полуночи не раздувает дневные кредиты тарифа.

Ключи
- У ключа новые настройки: «Ultra-модели» (allow_ultra), лимит запросов в сутки, лимит Ultra-кредитов в сутки.
- Новые ключи и ключи из «подключения одной командой» создаются БЕЗ доступа к Ultra. Старые ключи сохраняют доступ.
  Подключение одной командой никогда не выбирает Ultra-модель.
- Блокировка за перебор ключей блокирует только неверные попытки; верный ключ с того же IP работает.
- Перебор кодов подключения: не больше 10 неверных кодов за 10 минут на пользователя.

Нагрузка и память
- Слот и лимиты проверяются ДО чтения тела. Content-Length больше лимита — сразу 413.
- Общий бюджет тел в памяти (API_BODY_INFLIGHT_MB, 128 МБ) и доля одного пользователя (API_BODY_INFLIGHT_USER_MB, 64 МБ).
- Тело должно дойти за API_BODY_TIMEOUT_MS (60 с): медленная загрузка по байту больше не держит место.
- 50 тел по 30 МБ с одного ключа: пик памяти был 2,4 ГБ, стал ~0,45 ГБ. Один ключ больше не может занять бюджет и остановить остальных.
- Параллельных запросов на пользователя по умолчанию 10, на весь сервер 200 (API_GLOBAL_CONCURRENCY).
- count_tokens и /v1/models — свои лимиты частоты, не съедают лимит генерации.
- Глубокая вложенность JSON (больше 100 уровней) — сразу 400, без обращения к провайдеру (было 503/500).

Провайдеры и поток
- Прямая передача (Claude Messages, OpenAI Responses) отправляет провайдеру только разрешённые поля.
  Серверные инструменты (веб-поиск, code execution, MCP, container) не передаются за наш счёт.
  Запрос, где все инструменты серверные, получает понятную ошибку 400.
  Разрешённые anthropic-beta: interleaved-thinking, fine-grained-tool-streaming, token-efficient-tools, prompt-caching,
  extended-cache-ttl, claude-code, context-management (+ API_NATIVE_BETAS).
  Бюджет размышлений урезается ниже max_tokens.
  Responses: store=false; previous_response_id и conversation — ошибка 400 (ответы не хранятся).
- Ошибка «контекст слишком длинный» — только для ответов 400/413/422 (раньше и для 429/5xx).
- Запомненный лимит контекста — по провайдеру и модели, живёт 1 час, не ниже 1024.
- Keepalive провайдера продлевает таймер тишины. Тишина дольше MODEL_IDLE_TIMEOUT (180 с) — 504.
- Прямые запросы без потока ждут до 10 минут (было 180 с).
- Поток без finish_reason отдаётся как обрезанный (length / max_tokens / incomplete), а не как нормальный stop.
- finish_reason = tool_calls, если были вызовы инструментов.
- Медленный клиент: запись ответа ждёт до 60 с (API_WRITE_TIMEOUT_MS), потом соединение закрывается.
- Поток chat сразу отдаёт заголовки, а не с первым токеном.
- Кончились деньги у провайдера — оповещение администратору, ключ провайдера не попадает в журналы.

Сервер
- Остановка (systemctl restart): новые соединения не принимаются, запросы /v1 в работе получают до 5 с
  (SHUTDOWN_GRACE_MS) на завершение, остальные обрываются с возвратом. TimeoutStopSec=40 в deploy/premier.service.
- Заголовкам X-Real-IP / X-Forwarded-For верим только от прокси на этой же машине (TRUSTED_PROXIES).
- Мёртвый код удалён: public-api.js, api-keys.js, test/public-api.test.js, test/public-api-ui-smoke.js.
  Вкладка API в чате ведёт на /developers. Английская страница разработчика работает через /api/dev/*.
- Индекс api_log_at, схема в premier-db-schema.sql обновлена (колонки добавляются сами при запуске).

Новые переменные окружения (deploy/premier.env.example)
--------------------------------------------------------
API_BASE_URL               адрес API для кабинета и скрипта подключения. Не задан — https://ide.kgpix.bond (как раньше).
                           Пустое значение — PUBLIC_URL. Рекомендуем задать явно: API_BASE_URL=https://ide.kgpix.bond
TRUSTED_PROXIES            IP/подсети прокси, которым верим. По умолчанию только 127.0.0.1 и ::1.
SHUTDOWN_GRACE_MS          5000
API_CONCURRENCY            10 (было 6)
API_GLOBAL_CONCURRENCY     200
API_BODY_INFLIGHT_MB       128
API_BODY_INFLIGHT_USER_MB  2 × API_BODY_MB (64)
API_BODY_TIMEOUT_MS        60000
MODEL_IDLE_TIMEOUT         секунды тишины от провайдера, по умолчанию 180
API_WRITE_TIMEOUT_MS       60000
API_NATIVE_BETAS           дополнительные префиксы anthropic-beta через запятую

Решения владельца
-----------------
- Поток, оборванный после начала ответа, списывается.
- Обрыв клиентом до первого токена возвращается, но не больше 20 раз в сутки на пользователя.

Как применить
-------------
1. Резервная копия: cp -a /opt/premier /opt/premier.bak-$(date +%F)
2. Распакуйте архив поверх /opt/premier (папка premier/ в архиве).
3. Удалите старые файлы (их нет в архиве изменений):
   cd /opt/premier && rm -f public-api.js api-keys.js test/public-api.test.js test/public-api-ui-smoke.js
4. В /etc/premier/premier.env добавьте API_BASE_URL=https://ide.kgpix.bond.
   Если прокси (nginx, Caddy) не на этой же машине или в Docker — добавьте TRUSTED_PROXIES=<IP прокси>.
5. Если меняли deploy/premier.service: cp deploy/premier.service /etc/systemd/system/ && systemctl daemon-reload
6. cd /opt/premier && npm test
7. systemctl restart premier
