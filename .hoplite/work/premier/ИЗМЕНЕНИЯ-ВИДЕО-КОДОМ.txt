ВИДЕО КОДОМ: АНИМАЦИЯ В ЧАТЕ → MP4 (2026-11-17)
===============================================

Что это
-------
Вместо старой генерации видео нейросетью модель в чате пишет анимацию кодом (HTML/CSS/JS, canvas, SVG, GSAP).
Анимация сразу играется в окне предпросмотра, а под ним появляется полоса «Видео кодом · N с · F к/с · WxH»
с кнопкой «Скачать MP4» (на английском — "Download MP4"). Сервер заново проигрывает страницу в Chromium по
кадрам (виртуальные часы, без реального времени), склеивает кадры в MP4 (H.264, yuv420p, faststart) через ffmpeg
и отдаёт файл на скачивание. Расход видео-лимитов не нужен: никаких обращений к видео-моделям нет.

Как модель понимает, что это видео
----------------------------------
- Запросы вида «сделай видео про кота», «ролик», «гифка», «оживи …», "make a video / animation" идут в режим
  artifact + anim (chat-policy.js: animRequest, directIntent, taskOf). «Сайт с анимацией», «кнопка с анимацией»,
  игры, вопросы «как сделать видео?», python/unity — как раньше, не анимация. «Нарисуй картинку для видео» — картинка.
- К системному промпту добавляется ANIMATION_NOTE (контракт): мета-тег
    <meta name="premier-animation" content="duration=8; fps=30; width=1920; height=1080">
  размеры 1920x1080, 1080x1920 или 1080x1080, фиксированная сцена с масштабированием, движение только от времени
  (CSS-анимации, WAAPI, GSAP с CDN, rAF по временной метке), без ввода и звука.
- Правки и продолжения открытой анимации остаются в режиме анимации (наследуют anim).
- Проверка HTML (browser.checkHtml с anim:true): не ругается на «почти пустую страницу» и мобильное переполнение,
  но требует мета-тег.

Маршрутизация (после ревью)
---------------------------
- Анимация — только когда глагол («сделай/создай/сгенерируй/сними/хочу/нужен…») и слово «видео/ролик/клип/анимация/гифка» стоят рядом (до четырёх слов).
- «Нарисуй…» — всегда картинка; «мультик/мультфильм/заставка» считаются только прямым дополнением («сделай мультик»), не «героя мультика».
- Код и просмотр («скрипт», «функция», «код», ffmpeg, bash, «посмотреть», youtube) — не анимация. «Видеоплеер», «video chat» — не ролик.
- Открыт обычный сайт/игра: «сделай анимацию загрузки», «анимация на кнопку» — правка сайта (как раньше). Новая анимация — по прямой
  просьбе про видео/ролик/клип/гифку или «с нуля».

Рекордер (animation.js)
-----------------------
- Пределы: до 60 с, 10–60 к/с, сторона 128–1920 (чётная); по умолчанию 8 с / 30 к/с / 1920x1080.
  Кадров не больше ANIM_MAX_FRAMES (сначала снижается fps, потом длительность). HTML до 2 МиБ. Файл до 200 МБ.
- Виртуальные часы (в странице): requestAnimationFrame, performance.now, Date, setTimeout/setInterval,
  document.timeline, CSS/Web Animations; Math.random с фиксированным зерном. Одинаковый код даёт одинаковый MP4.
- Кадры: JPEG (качество 92) в ffmpeg через image2pipe; пишется <файл>.part, по завершении переименовывается.
- Файл: data/files/<uid>/<fid>/animation.mp4; fid = sha256(версия, uid, html, параметры)[:16].
  Повторный клик по тому же коду — мгновенно из кэша (переживает перезапуск). Хранится ANIM_KEEP последних на человека.

API
---
- POST /api/animation/render  {html}  → 202 {id, state, ...} или 200 {state:'done', cached:true, url}.
- GET  /api/animation/render/:id      → ход: queued (позиция) / running (прогресс) / done (url) / error (code).
  Задание видит только владелец. Готовый MP4: /api/files/<fid>/animation.mp4 (?dl=1 — скачивание).
- Нужен вход (401 иначе). Ошибки: 400 bad_html, 413 слишком большой, 501 no_ffmpeg, 503 no_browser,
  429 busy (одно задание на человека; после отмены — пока запись не остановится), 429 rate (40 в час на человека), 503 queue_full.
- DELETE /api/animation/render/:id → отмена (см. ниже). Очередь общая; готовые задания помнятся 10 минут.

Переменные окружения
--------------------
  ANIM_RENDER_CONCURRENCY  одновременных записей, по умолчанию 1 (максимум 4)
  ANIM_RENDER_TIMEOUT      лимит одной записи, секунд, по умолчанию 480
  ANIM_MAX_FRAMES          максимум кадров, по умолчанию 1800
  ANIM_QUEUE_MAX           длина очереди, по умолчанию 20
  ANIM_KEEP                сколько роликов хранить на человека, по умолчанию 10
  FFMPEG_PATH              путь к ffmpeg, если не в PATH
  Уже существующие: CHROMIUM_PATH, BROWSER_NO_SANDBOX, BROWSER_PAGES.

Требования к серверу
--------------------
- Chromium через puppeteer или playwright (как для проверки страниц) и ffmpeg.
- deploy/install.sh теперь ставит ffmpeg (apt-get install ffmpeg); вручную: apt install -y ffmpeg.
- ВАЖНО: запись держит страницу браузера до нескольких минут. Оставьте BROWSER_PAGES не меньше 2 (по умолчанию 2),
  иначе проверки HTML в чате будут ждать окончания записи. Запись 1920x1080 при 8 с (240 кадров) — порядка десятков секунд.
- Без ffmpeg или браузера сервер отвечает 501/503 с понятным текстом; живой предпросмотр работает всегда.


Безопасность и ресурсы записи (ревью)
-------------------------------------
- Сеть при записи: страница ходит только за своими ресурсами (ассеты пользователя) и на CDN из списка:
  cdn.jsdelivr.net, unpkg.com, cdnjs.cloudflare.com, fonts.googleapis.com, fonts.gstatic.com, esm.sh, ajax.googleapis.com
  (только https, без порта и логина). Всё остальное (чужие сайты, картинки с других доменов) браузер обрывает;
  WebSocket и EventSource в странице отключены. Список — HOSTS в animation.js; о нём сказано в ANIMATION_NOTE:
  внешних картинок нет, рисовать в SVG/Canvas или использовать data: URL.
- Параллельные записи: не больше min(ANIM_RENDER_CONCURRENCY, BROWSER_PAGES − 1), но не меньше 1, чтобы чату
  (самопроверка кода, веб-инструменты) всегда оставалась вкладка. При BROWSER_PAGES=2 (по умолчанию) — одна запись.
  Если поднимаете ANIM_RENDER_CONCURRENCY, поднимайте и BROWSER_PAGES.
- Отмена: DELETE /api/animation/render/:id (только владелец; чужой — 404). Очередь — запись выходит из очереди; идущая —
  останавливается, ffmpeg убивается, .part удаляется. Клиент вызывает её сам, если закрыть окно предпросмотра, открыть
  другую версию или уйти со страницы во время записи (best effort). Отдельной квоты по тарифу нет: остался только
  часовой предел 40 записей на человека.
- Ожидание шрифтов и картинок перед записью ограничено ~4 секундами настоящего времени (ленивые <img loading=lazy> загружаются сразу).
- Если ffmpeg завершился посреди записи (ошибка или предел файла 200 МБ), запись сразу заканчивается ошибкой с текстом ffmpeg
  (или «видео получилось слишком большим»), а не висит.
- При остановке сервера (SIGTERM/SIGINT/exit) живые ffmpeg убиваются, недописанные .part удаляются; prune также убирает
  папки неудавшихся записей (пустые или только с .part).
- Правка открытой анимации: к промпту добавляются только правила анимации (ANIMATION_EDIT_NOTE), без «верни целый HTML» —
  формат ответа задаёт протокол точечных правок.
- Виртуальные часы: Date() без new возвращает строку; CSS/Web-анимации, стоявшие на паузе и запущенные позже, подхватываются.

Старая генерация видео удалена полностью
----------------------------------------
- Из админки убраны настройки видео, из тарифов — поле videos; маршруты /api/admin/video и intent 'video' удалены.
- Файл video.js удалён из репозитория. На сервере его нужно удалить вручную: rm -f video.js
  (при копировании файлов поверх старой установки он останется).
- При запуске сервер один раз удаляет из настроек старый ключ settings.video (мог хранить apiKey прежнего провайдера).

Как применить
-------------
1. Скопировать файлы (список ниже), удалить video.js (rm -f /opt/premier/video.js),
   на сервере выполнить apt install -y ffmpeg. Нужен Chromium через puppeteer/playwright (как для проверки страниц).
2. npm test, затем перезапустить сервис. Ничего в базе менять не нужно.
3. В чате: «сделай видео про кота» → дождаться кода → «Скачать MP4».

Учёт лимитов
------------
Анимация, созданная в чате, считается как обычный сайт/артефакт (существующий счётчик bill.add(user.id,'s')).
Сама запись MP4 лимитов тарифа не тратит; защита — 40 записей в час и одна одновременная на человека.

Что не проверено
----------------
- Живой ответ модели в чате (маршрутизация и ANIMATION_NOTE проверены тестами, но не на реальной модели).
- Запись через playwright (проверялся только puppeteer; сетевой фильтр в ветке playwright написан так же, но не запускался); GSAP/скрипты с CDN через прокси ресурсов.
- Работа на боевом сервере без ffmpeg/Chromium — проверен только ответ API 501/503.
- Тесты test/chat-server.test.js («401/429…») и test/artifact-server.test.js падают и на исходном b32a0dc —
  к этой работе не относятся.
