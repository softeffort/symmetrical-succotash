ПАКЕТЫ СООБЩЕНИЙ, АВТОСБРОС И «МОИ ПЛАТЕЖИ» (2026-11-16)
=========================================================

Зачем
-----
По переписке с клиентом (тариф Max, 1000 сообщений в день):
- «Оплатил сброс — не сработал». Сброс применялся в момент подтверждения оплаты.
  Если человек платил заранее, не дойдя до лимита (или крипта подтверждалась позже),
  сброс обнулял неизрасходованный остаток — деньги фактически сгорали.
- «Когда сбросятся лимиты? В 22 по МСК?» — на Pro и Max над полем ввода не было ни
  счётчика, ни времени сброса.
- «Купил бы разом больше, устал делать сбросы» — не было способа купить объём заранее.
- «Платёж прошёл, лимиты не сбросились» — клиент не видел статус своих платежей и писал в личку.

Что изменилось
--------------
1. Автосброс
   - Купленный сброс больше не тратится «вслепую» при оплате. Если лимит в этот момент уже
     исчерпан — тратится сразу (как раньше). Если нет — ложится на баланс.
   - Когда дневные сообщения заканчиваются, а на балансе есть сброс, он тратится сам —
     сообщение уходит без ошибки и без кнопок. В истории сбросов — запись «auto».
   - Автосброс можно выключить в окне «Лимиты и покупки» (по умолчанию включён).
   - Кнопка «Использовать сброс сейчас» осталась — например, если кончились картинки.

2. Пакеты сообщений
   - Покупаются сверх дневного лимита, тратятся только после него, сгорают через N дней
     (по умолчанию 30). Учитывается вес модели — как и в дневном лимите.
   - Порядок списания после дневного лимита: пакет → бонус за приглашение → автосброс.
   - По умолчанию: 1000 — 190 ₽, 3000 — 490 ₽, 10 000 — 1390 ₽ (меняются в панели).
     Цены выбраны так, чтобы пакет был выгоднее сброса (сброс на Max = 200 ₽ за до 1000 сообщений).
   - Промокоды на пакеты не действуют. Пакет не расходует скидку первой покупки
     и не считается оплатой тарифа для «Пригласи друга».
   - Возврат платежа (CHARGEBACKED) обнуляет остаток пакета.
   - Если ответ модели не пришёл (502, ошибка провайдера, пустой ответ), сообщение возвращается
     туда, откуда списано: в дневной лимит, в пакет или в бонус за приглашение — в чате и в API.

3. Защита от минуса (Панель → Тарифы → «Пакеты сообщений»)
   - Поле «Себестоимость 1 сообщения, ₽» — сколько в среднем платите провайдеру за
     сообщение веса 1. Возле каждого пакета — наценка и прибыль, цветом: красный < 0,
     жёлтый < «Минимальная наценка», зелёный — норма.
   - Пакет дешевле себестоимости сохранить нельзя: сервер ответит ошибкой.
   - Пока себестоимость не задана, проверка не работает — заполните поле.

4. Окно «Лимиты и покупки» (чат, RU и EN)
   - Сколько сообщений осталось сегодня, когда обновится лимит — по Москве и по времени
     пользователя («у вас 02:00»), сколько осталось.
   - Пакеты: остаток и срок каждого, покупка в один клик.
   - Сбросы: баланс, автосброс, «Использовать сейчас», «Купить сброс».
   - «Мои платежи»: последние 15 со статусами (Ожидает / Оплачен / Отменён / Возврат);
     у ожидающего — кнопка «Проверить», которая сразу перепроверяет счёт у платёжки.
   - Открывается: кнопкой «Лимиты» в строке над полем ввода, кнопкой «Сбросить лимит»
     (старое окно сброса заменено) и само, когда на Pro/Max закончились сообщения.

5. Строка над полем ввода для Pro и Max
   «Осталось 360 из 1000 сообщений на сегодня · пакет 2 400 · 1 сброс · новые в 00:00 МСК (у вас 02:00)».
   На Free — как раньше (15-growth.js).

6. Сообщение после оплаты — честное: «Лимит сброшен» только если он действительно сброшен,
   иначе «Сброс на балансе — спишется сам, когда закончатся сообщения». Для пакета — «+N сообщений».

API (новое)
-----------
POST /api/billing/auto-reset {on: true|false}  → { ok, billing }
GET  /api/billing/payments                      → { payments: [{ order, plan, amount, status, created, paid, qty, pack, ... }] }
POST /api/pay/create {plan: "pack", n: 1000, method}  — покупка пакета
GET  /api/billing → новые поля packs { left, list, offers, days } и autoReset
GET  /api/pay/check → для пакета поле pack (размер)

Как применить
-------------
1. Сделайте бэкап (deploy/backup.sh) и остановите сервис: systemctl stop premier
2. Распакуйте архив ПОВЕРХ существующей папки проекта (пути как в проекте, папка premier/ — корень).
   Папку целиком не удаляйте и не заменяйте: в архиве нет data/ (база, файлы пользователей),
   node_modules/ и tts/vosk/ — они есть только на сервере. Полный архив отличается от «только изменений»
   лишь тем, что содержит и неизменённые файлы.
3. Проверьте: npm test   (новые тесты — tests/packs.test.js, 8 штук)
   Дополнительно: node --test test/resets.test.js
4. Запустите: systemctl start premier
5. Панель → Тарифы → «Пакеты сообщений»: укажите себестоимость сообщения, проверьте цены, «Сохранить тарифы».
6. Откройте чат на Pro/Max: над полем ввода — строка со счётчиком и кнопкой «Лимиты».
